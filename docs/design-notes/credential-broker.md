# Credential broker

Part of the Keep It in Your Box design notes (`docs/design-notes/`). See `CLAUDE.md` for the rules
that reference this.

`kib/broker/`, host-side sidecar (`cap-drop=ALL`, no devices) on a user-defined bridge (alias `kib-broker`). The agent gets `ANTHROPIC_BASE_URL` → broker, a **placeholder** `CLAUDE_CODE_OAUTH_TOKEN`, and a **synthetic** `.credentials.json` shadowing the real one (all three needed: the env var is what Claude authenticates with; the shadow stops the real file being read). The broker strips the placeholder, injects the real token, re-originates TLS to `api.anthropic.com` — no MITM, no CA in the agent; the token never enters the sandbox (fixes audit H3/H4 for the brokered path).

**ON by default** — `broker_wanted` reads the parsed config value `KIB_CFG_BROKER`, which defaults to
`on`; disable with `broker = off` in `~/.keep-it-in-your-box/config`, or `KIB_BROKER=0` for one
launch (`KIB_BROKER=1` forces it on).

- **Two namespaces, never merged:** `KIB_CFG_*` is the parsed *config file*, bare `KIB_*` is the
  user-facing environment override. Sharing one name lets the two silently clobber each other.
- **Fail-safe spelling:** `broker_wanted` enumerates the recognised *off* spellings
  (`off`/`0`/`no`/`false`) rather than testing `!= on`, so a typo (`broker = of`) falls through to
  the safe side — brokered — instead of silently mounting the real credential.
- **First run:** an *interactive* launch with no token auto-runs `provider_login claude` (wraps
  `claude setup-token`) in a subshell; the static token lands host-only. With no token and no
  interactive login (headless, or declined), `start_broker` falls back to the pre-broker path —
  `stage_credential` copies the real `~/.claude/.credentials.json` into the shared-assembly
  **directory** (never a single-file bind — the rename footgun below) and `merge_out_credential`
  folds a changed copy back on exit.
- **Fail-hard on create** (it's the agent's auth), fail-safe mid-session (never re-mounts the real
  token). Wired via `start_broker`/`stage_credential`/`add_broker_env_args`/
  `connect_broker_network`/`verify_broker_attach`/`stop_broker`; bind-mounted, so edits land next
  launch while the running sidecar keeps old code.

## The "Claude API" banner is transport, not metered billing

Claude Code prints your plan name (`Claude Max`/`Claude Pro`) only when it runs its own `/login`
flow and reads the plan back from Anthropic. Through the broker the agent just sees
`ANTHROPIC_BASE_URL` pointed at a raw endpoint, so the startup banner falls back to the generic
**"Claude API"** descriptor. That is a statement about *how the request leaves*, not about how it's
billed — a brokered session still says "Claude API" even though nothing changed about your plan.

Billing is decided by the **token** the broker injects, not the label. The Anthropic row mints
`sk-ant-oat01-…` (from `kib broker login`, which wraps `claude setup-token`) and injects
`Authorization: Bearer …` + `anthropic-beta: oauth-2025-04-20` — that `oat01` + OAuth-beta shape
*is* subscription (Pro/Max) auth, so usage counts against your plan. Metered per-token billing
would instead be an `sk-ant-api…` console key sent as `x-api-key` with no OAuth beta header; a
`setup-token` login never configures that. So: same subscription, just routed through the broker,
which is why the banner reads "Claude API".

![Claude Code startup banner reading "Opus 4.8 (1M context) with high effort · Claude API" while brokered onto a Pro/Max subscription](../../docs/assets/readme/claude-api-banner.png)

- **`CLAUDE_CODE_OAUTH_TOKEN` reading as *unset* inside a session is normal, not a regression.** Claude Code consumes it at startup and scrubs it from the environment it hands tool shells and subagents, so a `security-test.sh` run launched from a Bash tool call sees nothing, while `kib exec ./tests/security-test.sh` — its own `docker exec` — sees the placeholder. The suite therefore falls back to the agent's `/proc/<pid>/environ` (the exec-time snapshot, unaffected by `unsetenv`), so a *real* token in the container is still caught in the scrubbed case, where a plain skip would have missed it.
- **The synthetic `.credentials.json` is read-only by MOUNT, never by mode.** It used to be a `cp` + `chmod 0400`; Docker Desktop's `fakeowner` bind layer records the mode but ignores it in `access(2)`, so on macOS the placeholder shipped writable and the control was a silent no-op. It is a flat `:ro` bind via `bind_via_link` now (the destination nests inside the shared-dir mount, which would otherwise abort `docker run`). Nothing refreshes it under the broker, so a single-file bind carries none of the rename risk the real rotating credential does. `macos.md`, guarded in `regressions.sh`.
- **The brokered credential is STATIC and the broker has no write path. DO NOT reintroduce a refresh loop, and never broker `.credentials.json`.** The secret is a long-lived token from `kib broker login` (wraps `claude setup-token`) at `~/.keep-it-in-your-box/claude-token`, mounted `:ro`. Structural, not fixable: Anthropic subscription refresh tokens are **single-use and rotating**, so the first refresher invalidates the family for the host CLI and every other sidecar (upstream issues #56339/#54443/#60503) — a refresh loop logs the account out permanently. Guarded three ways: `tests/broker/test_broker.py` asserts no refresh functions exist under any name, `mint_placeholder` takes no real-credential path + serves with a `0400` token, and `check.sh` asserts `.credentials.json` is never bind-mounted and the token mount carries `:ro`. The rule holds for **every** provider — Codex/Gemini subscription OAuth rotates too; broker a *key*, not the OAuth.
- **The upstream origin is pinned, and the LLM routes pin the PATH set too** (`allow_paths`, audit MAC-L2/R3). A fixed upstream stops the credential being redirected; it does not stop the box driving *any* authenticated request the token permits at that upstream — account reads, key minting. Each built-in LLM row now names the prefixes Claude Code actually uses (`/v1/` plus the read-only `/api/oauth/profile` for claude); everything else 404s with a `BROKER-DENY-PATH` breadcrumb and never leaves the sidecar. Matched on the path component only, so `?beta=true` cannot turn an allowed path away — but on the path the upstream *resolves*, not the bytes we forward: percent-escapes are decoded and `.`/`..` collapsed first (else `/v1/../api/oauth/…/create_api_key` walks through a `/v1/` prefix and the origin's own RFC 3986 normalisation lands it on the mint), and prefixes match segment-wise (`/api/oauth/profile` is not `/api/oauth/profileEVIL`). **User MCP routes default to unrestricted** — their endpoint sets are not knowable here and a wrong guess breaks the route silently, whereas the LLM rows carry the user's real account token and a known client. Add `allow_paths` to a user def to opt in.
- **Dual-homing — do not drop `connect_broker_network`.** The main container stays on the default bridge + `host.docker.internal` (host dev servers, LAN) *and* joins the broker net.
- **Only the LLMs (`claude`/`codex`/`gemini`) are built into `PROVIDERS`; no MCP is hardcoded.** `PROVIDERS` is the single source of truth (bash reads it via `host-config`/`list-providers`). Users broker any MCP via partial dicts in `~/.keep-it-in-your-box/providers.d/*.json` (`_finalize_provider` fills defaults, `merge_user_providers` folds them in via `KIB_PROVIDERS_DIR`, mounted `:ro`). LLM built-ins are **not overridable** (a poisoned def can't redirect the Claude token). `examples/providers/{dataforseo,gsc}.json` are copy-in examples, not rows.
- **One shared MCP port, path-routed — a user route never has a port of its own.** LLM rows keep dedicated listeners (8080–8082) and forward the path **verbatim**. Every `reverse_proxy_mcp` route shares **`MCP_PORT` = 8100**, dispatched by a `/mcp/<id>` prefix that `make_mux_handler` strips before forwarding; each `hosted_mcp` sidecar reuses 8100 inside its own netns. `Host` staying in `HOP_BY_HOP` is what makes one listener serve N upstreams — `http.client` regenerates the right one per connection. `route_path`/`agent_url` are the single definition, so `inject`, `host-config` and `kib broker status` cannot print three different URLs. See the post-mortem below for why the knob is gone rather than validated.
- **Delivery modes** keyed off credential shape: `base_url_env` (LLMs: env + shadow file; codex/gemini rows ready-but-unstarted), `reverse_proxy_mcp` (remote MCP, static header: kib writes a header-free `http://kib-broker:8100/mcp/<id><mcp_path>` into the session's `.claude.json` `mcpServers` via `inject_brokered_mcps`; broker injects the header; relay unbuffered), `hosted_mcp` (client-signed creds the broker can't header-inject, e.g. a Google service-account JSON: the MCP *server* runs in its own `cap-drop=ALL` sidecar via `start_hosted_mcp`, supergateway bridging stdio→HTTP, credential `:ro`; agent reaches `http://<id>:8100<mcp_path>`; the MCP's own code is trusted — pin it). Hosted MCPs + `.claude.json` injection are **fail-soft** (never block a session); the Claude broker is fail-hard. `hosted_mcp` end-to-end is verify-on-first-real-use, same as codex/gemini rows.
- **Fail-soft is per ROUTE, and `FAIL_HARD_ROUTES = ("claude",)` is the whole list.** Every bind goes through `_bind`, which returns `None` instead of raising; `_build_routes` resolves the enabled set without binding anything (so the split is testable in CI without touching 8100). A route that cannot come up lands in `$BROKER_OUT/broken` as `<id> <reason>`, written **before** `ready` — the host only reads it after seeing `ready`, so that order is what makes the report complete rather than racy. `start_broker` warns per line and carries on; only a failed `claude` route aborts.
- **Every refusal names the field.** `_validate` returns one message per fault, prefixed `providers.d/<file>:` — a missing key, an `upstream_origin` carrying a path, an `id` disagreeing with the filename, an unsafe route name, and the two `_OBSOLETE` port keys. A file whose name lacks `.json` is reported too, rather than skipped in silence. They collect in `DEF_PROBLEMS`, which `kib broker status` and the top of `start_broker` print host-side via `check-providers` (they used to reach only the sidecar's stderr, in a different container) and `serve` logs as `BROKER-BADDEF`. Never echo file content: a def sits next to credentials.
- **`validate_route_id` is one validator for three jobs** — a filename stem, a URL path segment, and a `list-providers` field bash word-splits on. Enforced at the writer (`kib broker add`, `mcp adopt`, `intercept`) *and* the reader (`merge_user_providers`), because a def can also be hand-copied in.
- **`kib broker add` wraps `kib mcp add`, it does not replace it.** `mcp add` stays the non-interactive machinery `adopt`/`intercept` share; `add` closes its one real gap — it wrote a def and then told you to run a *second* command. Bare + a tty runs `_broker_add_wizard` (prompts only); everything else goes straight to argparse, because bash may only ever detect "no args", never parse a flag (`kib/shared/cli.py`). `_broker_add_finish` re-reads `list-providers` and dies if the def it just wrote failed validation — that round trip is the end-to-end guarantee — then chains `provider_login`, so the wizard never handles a secret itself. `add` refuses an existing name without `--force`; `intercept` overwrites deliberately (re-pasting a rotated vendor line should update the route).
- **The attach hash folds in a route fingerprint** (`id|route_path|upstream`), not just the ids: editing a def's upstream used to leave a running sidecar serving the old one while a second terminal attached happily. It means more attach refusals after an edit, which is the correct behaviour.

### Post-mortem: `OSError: [Errno 98] Address already in use`

An agent in an unrelated workspace was asked to broker a Directus MCP. `guest/policy/etc-CLAUDE.md` said nothing about the broker, so it invented a procedure: hand-author a providers.d file with a hardcoded `listen_port`. The port collided, the sidecar died, and the launch aborted. Four independent defects, all now closed:

1. **A per-route port knob existed at all.** `next_free_port()` was `max()+1` over the in-process table — it never probed and never checked uniqueness; `--port` was unvalidated; `_write_broker_config` did not pre-flight the enabled set. Auto-assignment does not fix a number the user can still edit, so the knob is **deleted** rather than validated.
2. **The bind was unguarded** — the one `socket.bind()` in the package had no `try`, unlike the mint two lines above it, so an `OSError` escaped PID 1: every already-bound route died, `ready` was never written, and the whole launch aborted for one broken MCP.
3. **Validation said nothing useful** — `skipping incomplete provider def` named no field, and a file whose name lacked `.json` was skipped in total silence.
4. **`examples/providers/README.md` taught the bad pattern verbatim**: *"The copies above pin 8100/8101 — change them if they collide with another route you've added."*

The UX root cause was the fifth: with no broker section in the policy file, an agent elsewhere could not know `kib broker add` existed. That section is now the fix for the *class*, and the four above are the fix for the instance.
- **Credential lifecycle:** `kib broker add|login|logout|status|probe [provider]`, registry-driven (`provider_login/logout/status`), dispatched **after** sourcing but **before** `preflight_platform`/`build_image_if_missing` so they work with a broken image. `paste_token` providers read a hidden paste; `file_path` providers copy a JSON key mode 600. `status` prints size/mode only, never contents; `probe` checks the stored token against the provider — the claude probe distinguishes rejected (401/403 → exit 1) from inconclusive (429/5xx/network → exit 2). Branches use `provider_x && exit 0 || exit $?` because a bare call trips `set -e`.
- **Inline-secret detection + adoption:** `warn_inline_mcp_secrets` scans `.mcp.json` + `.claude.json` every launch — warns, never blocks, never prints the value. `kib mcp adopt <name>` migrates an inline entry: reuses a matching user route (`match-upstream`) or **synthesizes** a `reverse_proxy_mcp` def from the existing config (URL → upstream+path, header → inject template, no port); stores the secret host-side (600) and strips it from the config. Refuses local/stdio (needs `--add-mcp … --run … --cred-env …`). Dispatches after identity resolution (touches the project dir), unlike the host-global subcommands.
- **Wrapper interception (`intercept_mcp_add`) — the front-line preventer.** A user swapping `claude`→`cc` on a vendor's `claude mcp add … --header "Authorization: …"` line would put the raw secret in the container's argv → `.claude.json`; nothing inside the box can fix that. `kib` catches `[claude] mcp add|add-json` **host-side before any `docker exec`** (dir-guard-exempt so it works from `$HOME`). Tri-state: remote `--header` → **auto-broker** (writes the provider def + token, never runs the in-box add; if broker off, stages and says how to enable); local `--env`-secret → **block** (opt-out `KIB_ALLOW_INLINE_MCP_SECRET=1`); no secret / `mcp list` / plain session → **passthrough** (default, so a real launch is never swallowed). The secret-shape test, `synthesize_reverse_proxy`, and `store_secret` are shared helpers in `kib/broker/` — single source of truth imported by all four call sites, so blocker and warner can't drift. `find_auth_header` brokers the auth header wherever it sits (a decoy `Accept:` first no longer mis-brokers).
- **`~/.keep-it-in-your-box/`** — host-only, **never bind-mounted into the sandbox** (the agent can't rewrite what governs its own credentials/egress). `config` keys: `broker`, plus future E1 egress toggles (`egress`, `allow_host_services`, `allow_lan`, `lan_cidrs` — under `egress = restricted`, host/LAN default-deny). Also holds the static credentials (mode 600) and `providers.d/`.
