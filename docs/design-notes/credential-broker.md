# Credential broker

Part of the Keep It in Your Box design notes (`docs/design-notes/`). See `CLAUDE.md` for the rules
that reference this.

`kib/broker/`, host-side sidecar (`cap-drop=ALL`, no devices) on a user-defined bridge (alias `kib-broker`). The agent gets `ANTHROPIC_BASE_URL` → broker, a **placeholder** `CLAUDE_CODE_OAUTH_TOKEN`, and a **synthetic** `.credentials.json` shadowing the real one (all three needed: the env var is what Claude authenticates with; the shadow stops the real file being read). The broker strips the placeholder, injects the real token, re-originates TLS to `api.anthropic.com` — no MITM, no CA in the agent; the token never enters the sandbox (fixes audit H3/H4 for the brokered path).

**ON by default** — `broker_wanted` reads the parsed config value `KIB_CFG_BROKER`, which defaults to
`on`; disable with `broker = off` in `~/.keep-it-in-your-box/config`, or `KIB_BROKER=0` for one
launch (`KIB_BROKER=1` forces it on).

- **Two namespaces, never merged:** `KIB_CFG_*` is the parsed *config file*, bare `KIB_*` is the
  user-facing environment override. Sharing one name lets the two silently clobber each other.
- **Fail-safe spelling:** `broker_wanted` enumerates the recognised *off* spellings
  (`off`/`0`/`no`/`false`) rather than testing `!= on`, so a typo (`broker = of`) falls through to
  the safe side — brokered — instead of silently mounting the real credential.
- **First run:** an *interactive* launch with no token auto-runs `provider_login claude` (which
  runs `claude setup-token` in the image — never a host claude, see below) in a subshell; the
  static token lands host-only. With no token and no interactive login (headless, or declined),
  `start_broker` falls back to the pre-broker path —
  `stage_credential` copies the real `~/.claude/.credentials.json` into the shared-assembly
  **directory** (never a single-file bind — the rename footgun below) and `merge_out_credential`
  folds a changed copy back on exit.
- **Fail-hard on create** (it's the agent's auth), fail-safe mid-session (never re-mounts the real
  token). Wired via `start_broker`/`stage_credential`/`add_broker_env_args`/
  `connect_broker_network`/`verify_broker_attach`/`stop_broker`; bind-mounted, so edits land next
  launch while the running sidecar keeps old code.

## The first run, where there is no host `claude` — because there never is

Three separate dead ends, all on the same launch: the one where the user has just installed kib
and nothing else. Each was reported from a fresh macOS install (2026-08-15).

- **The token is minted in the IMAGE. Never require a host `claude` — the absence of one is the
  premise of the whole project.** `_provider_login_hint` used to check `command -v claude` and,
  on a miss, print "run `claude setup-token` on the host", which dead-ends a new user at a hidden
  paste prompt with nothing to paste and a CLI they installed kib specifically to avoid. There is
  no host-install path here and there should never be one (an offer to `curl | bash` the official
  installer was written and thrown away for exactly that reason). `_mint_claude_token` runs
  `docker run --rm -it --entrypoint="" $IMAGE_NAME claude setup-token`: the same Claude Code the
  box runs, on an image `build_image_if_missing` has already guaranteed (a bare `kib broker login`
  is the one path that can precede it, and it says `kib build` instead of failing obscurely).
  `--entrypoint=""` skips kib's entrypoint, which expects mounts this run does not have — the same
  shape as `check_for_updates`' version probe.
  - **That throwaway container is not "the sandbox", and the invariant it must not break is about
    the sandbox.** No project bind, no session dir, no shared assets, no broker network, no agent,
    `--rm`: nothing it sees outlives the command, and the token was always going to cross the
    user's terminal on its way to the paste prompt. What the rule forbids is the real credential
    reaching the container the *agent* runs in, which this is not.
  - The cost is one extra step: no browser can open in there, so it prints a URL to open on the
    host and takes the code back. That is the trade for never needing a host install.
- **Two pastes that store fine and fail far away** — `_vet_pasted_secret`, split out of
  `provider_login` so the check suite can drive it without a tty. A pasted **path** was stored
  verbatim, and `read` takes one line, so a pasted `.credentials.json` stored `{`. Both then
  failed at the probe, or worse: the accessToken *inside* that file is the rotating one, so it
  probes green and 401s hours later. Refuse all three at the prompt, where the reason can still
  reach the user.
- **A brokered box must never run Claude Code's own login, and onboarding IS that login.** Its
  first-run flow puts "Select login method" on screen whenever `hasCompletedOnboarding` is falsy —
  it does not care that a token is present. On a new machine canonical `.claude.json` does not
  exist yet, so the first launch ever opened on a login prompt with a working brokered token
  behind it, and choosing anything there tries to mint a credential the sandbox may not see.
  `seed_brokered_config` → `kib.host.pins seed-brokered` seeds the flag into the *session*
  `.claude.json` (never canonical — merge-out is `projects[path]`-only, so nothing about this
  leaks back out). A **seed**, not a pin: written only when absent, so the user still owns the
  key. Gated on `BROKER_ENABLED=1`, and that gate is the point — with no token the real credential
  is staged instead and an in-box login is exactly the right offer.

## The "Claude API" banner is transport, not metered billing

Claude Code prints your plan name (`Claude Max`/`Claude Pro`) only when it runs its own `/login`
flow and reads the plan back from Anthropic. Through the broker the agent just sees
`ANTHROPIC_BASE_URL` pointed at a raw endpoint, so the startup banner falls back to the generic
**"Claude API"** descriptor. That is a statement about *how the request leaves*, not about how it's
billed — a brokered session still says "Claude API" even though nothing changed about your plan.

Billing is decided by the **token** the broker injects, not the label. The Anthropic row mints
`sk-ant-oat01-…` (from `kib broker login`, which runs `claude setup-token` in the image) and injects
`Authorization: Bearer …` + `anthropic-beta: oauth-2025-04-20` — that `oat01` + OAuth-beta shape
*is* subscription (Pro/Max) auth, so usage counts against your plan. Metered per-token billing
would instead be an `sk-ant-api…` console key sent as `x-api-key` with no OAuth beta header; a
`setup-token` login never configures that. So: same subscription, just routed through the broker,
which is why the banner reads "Claude API".

![Claude Code startup banner reading "Opus 4.8 (1M context) with high effort · Claude API" while brokered onto a Pro/Max subscription](../../docs/assets/readme/claude-api-banner.png)

- **`CLAUDE_CODE_OAUTH_TOKEN` reading as *unset* inside a session is normal, not a regression.** Claude Code consumes it at startup and scrubs it from the environment it hands tool shells and subagents, so a `security-test.sh` run launched from a Bash tool call sees nothing, while `kib exec ./tests/security-test.sh` — its own `docker exec` — sees the placeholder. The suite therefore falls back to the agent's `/proc/<pid>/environ` (the exec-time snapshot, unaffected by `unsetenv`), so a *real* token in the container is still caught in the scrubbed case, where a plain skip would have missed it.
- **The synthetic `.credentials.json` is read-only by MOUNT, never by mode.** It used to be a `cp` + `chmod 0400`; Docker Desktop's `fakeowner` bind layer records the mode but ignores it in `access(2)`, so on macOS the placeholder shipped writable and the control was a silent no-op. It is a flat `:ro` bind via `bind_via_link` now (the destination nests inside the shared-dir mount, which would otherwise abort `docker run`). Nothing refreshes it under the broker, so a single-file bind carries none of the rename risk the real rotating credential does. `macos.md`, guarded in `regressions.sh`.
- **The brokered credential is STATIC and the broker has no write path. DO NOT reintroduce a refresh loop, and never broker `.credentials.json`.** The secret is a long-lived token from `kib broker login` (runs `claude setup-token` in the image) at `~/.keep-it-in-your-box/claude-token`, mounted `:ro`. Structural, not fixable: Anthropic subscription refresh tokens are **single-use and rotating**, so the first refresher invalidates the family for the host CLI and every other sidecar (upstream issues #56339/#54443/#60503) — a refresh loop logs the account out permanently. Guarded three ways: `tests/broker/test_broker.py` asserts the LLM row can never carry a mintable credential, `mint_placeholder` takes no real-credential path + serves with a `0400` token, and `check.sh` asserts `.credentials.json` is never bind-mounted and the token mount carries `:ro`.
  **Amended 2026-08-01 — the rule is now scoped, and the scoping is the point.** What caused the logout was *writing* a credential, not *minting* one: a rotating refresh token persisted back to disk invalidates the family for every other holder. So the invariant that survives is **the broker has no write path to any credential, ever**, and it is absolute. A USER route may declare `credential_kind: oauth` and mint short-lived access tokens (`kib/broker/oauth.py`) because that never writes anything — the token is a return value held in memory by `Credential`, and a `refresh_token` in a grant response is **discarded** with a one-time `BROKER-ERR` naming the route. The LLM row stays `paste_token` and is barred from the OAuth path by test. Do not widen this back to "the broker may refresh the Claude credential": subscription OAuth still rotates, and there is still nowhere safe to put the result.
- **The upstream origin is pinned, and the LLM routes pin the PATH set too** (`allow_paths`, audit MAC-L2/R3). A fixed upstream stops the credential being redirected; it does not stop the box driving *any* authenticated request the token permits at that upstream — account reads, key minting. Each built-in LLM row now names the prefixes Claude Code actually uses (`/v1/` plus the read-only `/api/oauth/profile` for claude); everything else 404s with a `BROKER-DENY-PATH` breadcrumb and never leaves the sidecar. Matched on the path component only, so `?beta=true` cannot turn an allowed path away — but on the path the upstream *resolves*, not the bytes we forward: percent-escapes are decoded and `.`/`..` collapsed first (else `/v1/../api/oauth/…/create_api_key` walks through a `/v1/` prefix and the origin's own RFC 3986 normalisation lands it on the mint), and prefixes match segment-wise (`/api/oauth/profile` is not `/api/oauth/profileEVIL`). **User MCP routes default to unrestricted** — their endpoint sets are not knowable here and a wrong guess breaks the route silently, whereas the LLM rows carry the user's real account token and a known client. Add `allow_paths` to a user def to opt in.
- **Dual-homing — do not drop `connect_broker_network`.** The main container stays on the default bridge + `host.docker.internal` (host dev servers, LAN) *and* joins the broker net.
- **Only `claude` is built into `PROVIDERS`; nothing else is hardcoded.** `PROVIDERS` is the single source of truth (bash reads it via `host-config`/`list-providers`). Users broker any service via partial dicts in `~/.keep-it-in-your-box/providers.d/*.json` (`_finalize_provider` fills defaults, `merge_user_providers` folds them in via `KIB_PROVIDERS_DIR`, mounted `:ro`). The LLM row is **not overridable** (a poisoned def can't redirect the Claude token) and `delivery` is set by `_finalize_provider`, never declared by a def. `examples/providers/{dataforseo,gsc}.json` are copy-in examples, not rows. The `codex`/`gemini` rows were deleted (2026-08-01): ready-but-unstarted for their whole life, never enabled, never verified — another LLM CLI is a user route like anything else.
- **One shared port, path-routed — a user route never has a port of its own.** The LLM row keeps a dedicated listener (8080) and forwards the path **verbatim**. Every proxy route shares **`MCP_PORT` = 8100**, dispatched by a `/mcp/<id>` prefix that `make_mux_handler` strips before forwarding. `Host` staying in `HOP_BY_HOP` is what makes one listener serve N upstreams — `http.client` regenerates the right one per connection. `route_path`/`agent_url` are the single definition, so `inject`, `host-config` and `kib broker status` cannot print three different URLs. See the post-mortem below for why the knob is gone rather than validated.
- **`token_basename` is validated as a bare FILENAME, not a path** (`helpers.validate_token_basename`). `start_broker` interpolates it straight into `-v "$KIB_DIR/$basename:/run/broker/token/<id>:ro"`, so a def carrying `../../../.ssh/id_rsa` mounts that file into the broker and the relay then injects its bytes as the route's auth header — to the def's *own* `upstream_origin`. That is arbitrary host-file exfiltration from a pasted provider def, and empty is the same bug by another route (`$KIB_DIR/` is a directory, `[ -s ]` is true for it, so the whole credential store binds). Providers.d is not mounted in the sandbox, so the box cannot write a def itself; the threat is a def copied from somewhere. Regression-guarded.
- **Two deliveries, and only one is user-reachable:** `base_url_env` (the LLM row: env var + shadow credential file) and `reverse_proxy` (everything else). What varies across user routes is not how they are served but **where the injected secret comes from** — `credential_kind`, either `paste_token` (the stored file IS the secret) or `oauth` (the stored file is a config; the broker mints an access token from it). The relay is credential-agnostic: it asks `Credential.current_secret()` and injects the answer.
- **`.claude.json` registration is opt-in** — only a route that sets `mcp_server_name` gets an `mcpServers` entry from `inject_brokered_mcps`. It used to default to the route id, which put every REST-only route into the session as an MCP server that Claude Code then reported as failed. A REST route is reached at the same `http://kib-broker:8100/mcp/<id>` URL with curl. `.claude.json` injection is **fail-soft** (never blocks a session); the Claude broker is fail-hard.
- **Fail-soft is per ROUTE, and `FAIL_HARD_ROUTES = ("claude",)` is the whole list.** Every bind goes through `_bind`, which returns `None` instead of raising; `_build_routes` resolves the enabled set without binding anything (so the split is testable in CI without touching 8100). A route that cannot come up lands in `$BROKER_OUT/broken` as `<id> <reason>`, written **before** `ready` — the host only reads it after seeing `ready`, so that order is what makes the report complete rather than racy. `start_broker` warns per line and carries on; only a failed `claude` route aborts.
- **Every refusal names the field.** `_validate` returns one message per fault, prefixed `providers.d/<file>:` — a missing key, an `upstream_origin` carrying a path, an `id` disagreeing with the filename, an unsafe route name, and the two `_OBSOLETE` port keys. A file whose name lacks `.json` is reported too, rather than skipped in silence. They collect in `DEF_PROBLEMS`, which `kib broker status` and the top of `start_broker` print host-side via `check-providers` (they used to reach only the sidecar's stderr, in a different container) and `serve` logs as `BROKER-BADDEF`. Never echo file content: a def sits next to credentials.
- **`validate_route_id` is one validator for three jobs** — a filename stem, a URL path segment, and a `list-providers` field bash word-splits on. Enforced at the writer (`kib broker add`, `mcp adopt`, `intercept`) *and* the reader (`merge_user_providers`), because a def can also be hand-copied in.
- **`kib broker add` is the only way to declare a route; the `kib mcp add` verb is gone** (2026-07-28). The claim it rested on — that `mcp add` was "the non-interactive machinery `adopt`/`intercept` share" — was false of the *verb*: `kib.host.mcp`'s `adopt` and `intercept` are separate argparse subcommands calling `helpers.synthesize_reverse_proxy` directly, and the python `host.mcp add` entry point they share is what `provider_add` still calls. The bash verb was a strict subset of `broker add` — no name validation, no proof the def loads, no credential chain, no printed URL — so it exited 0 on defs the broker would then refuse, which is the gap `broker add` exists to close. Bare + a tty runs `_broker_add_wizard` (prompts only); everything else goes straight to argparse, because bash may only ever detect "no args", never parse a flag (`kib/shared/cli.py`). `_broker_add_finish` re-reads `list-providers` and dies if the def it just wrote failed validation — that round trip is the end-to-end guarantee — then chains `provider_login`, so the wizard never handles a secret itself. `add` refuses an existing name without `--force`; `intercept` overwrites deliberately (re-pasting a rotated vendor line should update the route).
- **The attach hash folds in a route fingerprint** (`id|route_path|upstream`), not just the ids: editing a def's upstream used to leave a running sidecar serving the old one while a second terminal attached happily. It means more attach refusals after an edit, which is the correct behaviour.
- **The registry is walked twice on the create path, deliberately.** `_write_broker_config` writes `enabled` + `token_paths` from `broker_enabled_providers`; `start_broker` re-walks `list-providers` with the same predicate to build the `-v …:/run/broker/token/<id>:ro` mounts. Only the walk carries `basename` — the host filename — which is why the second consumer cannot take the first's id-only output. Collapsing them means widening `_active_providers` to `id|basename`, and that output is *also* `broker_config_hash`'s input, so every existing container's attach hash shifts to save six lines on the credential path. The drift it invites (a third delivery kind added to one predicate and not the other) is closed by a test instead: `tests/check/mcp.sh`, *"every enabled broker route gets its token mounted (both walks agree)"*, which extracts the real mount loop rather than restating it. Reviewed and declined 2026-07-28.

### Post-mortem: `OSError: [Errno 98] Address already in use`

An agent in an unrelated workspace was asked to broker a Directus MCP. `guest/policy/etc-CLAUDE.md` said nothing about the broker, so it invented a procedure: hand-author a providers.d file with a hardcoded `listen_port`. The port collided, the sidecar died, and the launch aborted. Four independent defects, all now closed:

1. **A per-route port knob existed at all.** `next_free_port()` was `max()+1` over the in-process table — it never probed and never checked uniqueness; `--port` was unvalidated; `_write_broker_config` did not pre-flight the enabled set. Auto-assignment does not fix a number the user can still edit, so the knob is **deleted** rather than validated.
2. **The bind was unguarded** — the one `socket.bind()` in the package had no `try`, unlike the mint two lines above it, so an `OSError` escaped PID 1: every already-bound route died, `ready` was never written, and the whole launch aborted for one broken MCP.
3. **Validation said nothing useful** — `skipping incomplete provider def` named no field, and a file whose name lacked `.json` was skipped in total silence.
4. **`examples/providers/README.md` taught the bad pattern verbatim**: *"The copies above pin 8100/8101 — change them if they collide with another route you've added."*

The UX root cause was the fifth: with no broker section in the policy file, an agent elsewhere could not know `kib broker add` existed. That section is now the fix for the *class*, and the four above are the fix for the instance.
- **OAuth 2.0 routes (`credential_kind: oauth`)** replaced `hosted_mcp` (2026-08-01). The stored file is a *config*, not a secret to forward, and its `type` picks the grant with no extra flags: `authorized_user` → refresh-token grant (what `gcloud auth application-default login` writes), `service_account` → JWT-bearer RS256, `client_credentials` → the generic machine grant. `Credential.current_secret()` stays the one interface the relay calls; it caches the config on `(mtime_ns, size)` as before and the minted token in memory until `EXPIRY_SKEW` before expiry, all under the existing lock (so a cold-cache herd collapses to one exchange). `check()` validates the config *shape only* at route build — minting there would put an HTTPS round trip on the launch path and let one blip mark a route broken for the container's whole life. `_do_relay` retries **once** on a 401 after `invalidate(stale)`, which is safe only because `_read_body` already buffers the body and no response bytes have been written yet. That re-mint is **gated twice** — the 401'd token must still be the cached one (so a burst of concurrent 401s costs one mint, not one each) and at most one forced mint per `REMINT_INTERVAL`. Ungated it is a live foot-gun rather than a nicety: a 401 does not always mean a dead token, and a request outside the consented scopes 401s *every time*, so a loop of them would re-mint per request, serialise every other request behind that lock, and walk the token endpoint into a 429 — which `current_secret()` surfaces as a 502 for the requests that were valid. The cache expiry is floored at half the lifetime for the same reason: a provider issuing a 60-second token would otherwise cache for 0s and mint on every request. `cryptography` is imported **lazily inside `_sign_rs256`**: `kib/broker/*` must import on python 3.9 / stock macOS, where it does not exist — a module-level import breaks `kib broker status` on the host, which is why `kib broker probe` shape-checks a service account and leaves the real mint to first launch. Scope enforcement is honest and asymmetric: mint-time for `service_account`/`client_credentials`, consent-time only for `authorized_user` (Google ignores a narrowing `scope` on a refresh grant).
- **Credential lifecycle:** `kib broker add|login|logout|status|probe [provider]`, registry-driven (`provider_login/logout/status`), dispatched **after** sourcing but **before** `preflight_platform`/`build_image_if_missing` so they work with a broken image. `paste_token` providers read a hidden paste; `oauth` providers copy a JSON config mode 600. `status` prints size/mode only, never contents; `probe` checks the stored credential — rejected (401/403, or a refused grant → exit 1) vs inconclusive (429/5xx/network → exit 2). Because `status` is host-global and dispatches before `kib_resolve_paths`, `$BROKER_OUT` is usually unset, so `oauth-state` prints scopes from the registry and adds live expiry only when a project's broker dir happens to be resolved; live mint failures reach the user through the `BROKER-ERR` notifier instead. Branches use `provider_x && exit 0 || exit $?` because a bare call trips `set -e`.
- **Inline-secret detection + adoption:** `warn_inline_mcp_secrets` scans `.mcp.json` + `.claude.json` every launch — warns, never blocks, never prints the value. `kib mcp adopt <name>` migrates an inline entry: reuses a matching user route (`match-upstream`) or **synthesizes** a proxy def from the existing config (URL → upstream+path, header → inject template, no port, and `mcp_server_name` set — everything reaching adopt really is an MCP); stores the secret host-side (600) and strips it from the config. Refuses local/stdio: a server that holds its own credential is not something a header-injecting proxy can take over. Dispatches after identity resolution (touches the project dir), unlike the host-global subcommands.
- **Wrapper interception (`intercept_mcp_add`) — the front-line preventer.** A user swapping `claude`→`cc` on a vendor's `claude mcp add … --header "Authorization: …"` line would put the raw secret in the container's argv → `.claude.json`; nothing inside the box can fix that. `kib` catches `[claude] mcp add|add-json` **host-side before any `docker exec`** (dir-guard-exempt so it works from `$HOME`). Tri-state: remote `--header` → **auto-broker** (writes the provider def + token, never runs the in-box add; if broker off, stages and says how to enable); local `--env`-secret → **block** (opt-out `KIB_ALLOW_INLINE_MCP_SECRET=1`); no secret / `mcp list` / plain session → **passthrough** (default, so a real launch is never swallowed). The secret-shape test, `synthesize_reverse_proxy`, and `store_secret` are shared helpers in `kib/broker/` — single source of truth imported by all four call sites, so blocker and warner can't drift. `find_auth_header` brokers the auth header wherever it sits (a decoy `Accept:` first no longer mis-brokers).
- **`~/.keep-it-in-your-box/`** — host-only, **never bind-mounted into the sandbox** (the agent can't rewrite what governs its own credentials/egress). `config` keys: `broker` — and only `broker`. Four E1 egress toggles (`egress`, `allow_host_services`, `allow_lan`, `lan_cidrs`) were once parsed here ahead of a proxy that stayed unscheduled; they were deleted 2026-07-28 because the parser accepted `egress = restricted` in silence and restricted nothing. Re-add the parse together with the implementation, never before it. Also holds the static credentials (mode 600) and `providers.d/`.
