# Sleep guard

Part of the Keep It in Your Box design notes (`docs/design-notes/`). See `CLAUDE.md` for the rules
that reference this.

`sleep-guard.sh`: one host-side daemon per terminal. Every 3s it samples `wchar` from `/proc/<pid>/io` for **its own session's** processes and takes the **largest delta by any single process**, holding `systemd-inhibit` while that exceeds `SLEEP_GUARD_MIN_BYTES`, releasing after 30s quiet. Cannot use `docker logs` (PID 1 is `sleep infinity`; exec output goes to the TTY). The sampling exec runs as the *host uid* deliberately — `/proc/<pid>/{io,environ}` are gated by `ptrace_may_access`, which root-without-`CAP_SYS_PTRACE` fails against a uid-1000 process. Tunables: `SLEEP_GUARD_GRACE`, `SLEEP_GUARD_MIN_BYTES`, `SLEEP_GUARD_DEBUG=1`, `SLEEP_GUARD_LID_SUSPEND`, `SLEEP_GUARD_SETTLE`.

- **Scoped per session, never the whole container** — container-wide sampling makes one working session inhibit for all N terminals. `cc` stamps the exec with a unique `CC_SESSION_TAG` (inherited across fork/exec; matched via `/proc/<pid>/environ`, no ppid walk). Passed to the sampling shell as `CC_GUARD_TAG` (different name) so that shell can't match itself.
- **Busiest process, never the sum** — the sum is what pinned sleep overnight: any growing set (container pids, one session's subagents) crosses a fixed threshold once big enough, however idle each member. Three idle tabs at ~300B each summed past 1024B all night. The max is flat in N. **The threshold was never the problem; the aggregation was** (idle 218–374B per poll, mid-turn spinner 1.4–2.4KB, streaming 3.5KB+, flush spikes 76–250KB; 1024B sits in the idle→spinner gap with ~4× headroom).
- **Only pids present in both consecutive samples count** — a mid-interval pid has no baseline so its lifetime total reads as one huge delta, and `resolv-sync.sh` respawns a `grep` every 3s.
- An **empty sample** reads as quiet and releases after GRACE — deliberately biased toward letting the machine sleep (10 consecutive polls vs. overnight drain).
- **Proactive suspend:** logind fires the lid-close suspend exactly **once**; blocked by the inhibitor, it's dropped, never retried — so a task finishing after lid-close stranded the machine awake till morning. On going idle the guard runs `systemctl suspend` itself, only when unambiguous: lid shut (`/proc/acpi/button/lid/*/state`), no external display (`/sys/class/drm/*/status`, non-eDP/LVDS/DSI connected → docked, keep working), no other `claude-code` inhibitor held. Retries each idle poll. **Post-resume SETTLE window** (`SLEEP_GUARD_SETTLE=15`): without it the guard re-suspended 273ms after wake and wedged s2idle.
- **DEAD ENDS:** `--what=idle` inhibitor (makes lid-close always suspend, killing running tasks — the block must stay, the re-trigger is the fix); summing CPU ticks (same scales-with-N failure); transcript mtime (chatty when idle, silent 55s mid-turn); Claude Code hooks (no hook fires during extended thinking/long streams — needs a timeout backstop, too complex). An idle-timeout alone is no substitute: lid-close-only machines would never sleep after a lid-shut task ends.
- macOS: `caffeinate -is`; no proactive-suspend port needed (macOS re-evaluates sleep on assertion release). `busiest_delta` is an awk delta-join (the file's one former `declare -A`).
